## ③ 静的解析

### Python（bandit 1.9.4、`backend/` のうち tests を除く 1,776 行）

| 指摘 | 場所 | 判断 |
|---|---|---|
| B324 弱いハッシュ（SHA1） | `qto/ifc_loader.py` 40行 | 読み込みプログラム自身の「指紋」を取り、古いキャッシュを使わないようにする目的。安全を守るための用途ではないので対応不要 |
| B403・B301 pickle の読み込み | `qto/ifc_loader.py` 10行・234行 | IFCを2回目から速く開くためのキャッシュ（`.qto_cache`）の読み書きに使う。キャッシュはアプリ自身が作る。**注意点は下に書く** |
| B404・B603・B607 外部プログラムの起動（4件） | `scripts/app_driver.py`・`scripts/site_export_check.py` | 開発用の確認スクリプト。決まったコマンド（このアプリのサーバー、`node --test`）を起動するだけで、外から来た文字は使わない。持ち運び版には入れていない |
| B310 URLを開く | `scripts/app_driver.py` 34行 | 自分のPCのサーバー（127.0.0.1）に問い合わせるだけ。同上 |

**注意点（キャッシュの扱い）**
pickle は、読み込むファイルの中にプログラムを仕込めます。そのため、他人が作った `.qto_cache` の中身を読み込むと、そのプログラムが動くおそれがあります。
アプリ自身が作ったキャッシュだけを使う限り、問題はありません。次の2つを守ってください。

- `.qto_cache` フォルダを、他人から受け取ったり、ほかのPCからコピーしたりしない
- 共有フォルダのIFCは、自分のPCにコピーしてから開く（画面の「IFCを開く」で選んだIFCは、アプリのフォルダの中にコピーしてから開くので、この心配はない）

## ④ 外部通信の有無

### コードの検索

| 確かめたこと | 結果 |
|---|---|
| 計算サーバー・計算エンジン・MCPサーバーが、通信用のライブラリ（requests・httpx・urllib・socket など）を読み込んでいるか | 読み込んでいない |
| サーバーの待ち受け先 | `HOST = "127.0.0.1"`（`backend/server.py`）。同じPCの中からしか接続できない |
| 画面（PC・タブレット）の通信先 | すべて自分のサーバー（`/api/...`）か、同じ場所のファイル。外部のURLへの通信やCDNの読み込みはない（`http://www.w3.org/2000/svg` は図形の名前空間を表す文字列で、通信ではない） |
| MCPサーバー | Claude Code との標準入出力でやり取りする。ネットワークは使わない |
| タブレットの「記録を共有」 | 端末の共有メニュー（`navigator.share`）を開くだけ。送り先は利用者が選ぶ。アプリが自動で送ることはない |

### 実際の通信の観察

- 方法：計算サーバーを確認用のポート 8766 で起動し、デモ用のIFCの読み込み → 5SL～6SL の計算 → 3D表示用の形状の取得、の間、そのプロセスと子プロセスの通信（TCP・UDP）を Windows の `Get-NetTCPConnection`・`Get-NetUDPEndpoint` で繰り返し記録した（約14秒）
- 結果：見えた通信は、**127.0.0.1 どうしの接続だけ**だった（待ち受けの 127.0.0.1:8766、画面の代わりに送った問い合わせ、Python が内部で使う自分自身への接続）。外部のアドレスへの接続、UDP の通信はなかった
- 限界：0.3〜0.5秒ごとの観察なので、それより短い一瞬の通信は見逃しうる。上のコードの検索とあわせて判断した
