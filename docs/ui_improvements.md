## 改善1：操作の流れをアプリが誘導する

モードの切替を利用者が考えなくても、「施工階を選ぶ →（必要なら）境界線を引いて工区名を付ける → 数量を打設リストに追加」が自然に進むようにします。工区割は任意です。1フロアを一度に打つ現場では、施工階を選んでそのままリストに追加するだけで終わります。

**1-a. 「境界線を引く」を押したら自動で平面表示にする**

- `setMode('boundary')` および `setMode('zone')` に入ったとき、3D表示なら `setView('plan')` を呼ぶ
- 「境界線は平面表示で引いてください」「工区名は平面表示で付けてください」のヒント文は不要になるので削除
- 逆に境界線・工区名モード中に3Dへ切り替えたら、モードを `view` に戻す（ボタンの点灯も解除）

**1-b. 境界線を確定したら、次にすることを示す**

- `confirmPending()` の最後で、境界線が1本以上あり工区名が未設定なら、ヒントに「線を足すなら次の通り芯をクリック。終わったら『工区名を付ける』へ」と出す
- 工区名モードの最中、すべての範囲に名前が付いたらヒントに「全部の範囲に名前が付きました。右の計算結果を確認してください」と出す（自動でモード解除はしない。付け直しがあるため）
- 「工区名を付ける」を境界線0本で押したら、モードに入る前に「先に境界線を引いてください」を通知し、境界線モードに入る

**1-c. モードボタンの挙動を分かりやすく**

- 現状は同じボタンをもう一度押すと解除。これは残しつつ、点灯中のボタンの文言を「境界線を引く…（終了はもう一度押すかEsc）」のように変えるか、点灯中はボタンの右端に「終了」を小さく添える
- `style.css` で `.mode.active` の色を、部材色と被らない濃い青の塗りつぶしにする（いま何のモードかを一目で分かるように）

**1-d. 初期の施工階を「モデル全体」から変える**

- `fillStoreys()` の初期値を、`localStorage` に保存した前回の施工階（同じIFC名のときだけ）→ なければ階の中央の階（例：階が10つなら5番目）の順で決める
- 「モデル全体」は選択肢の末尾に残す。全体数量の確認とデモで使うため
- 読込直後の3D表示（`loadModel()` の `setView('3d')`）はそのまま。ただし施工階を変えたときは `fit()` を呼び直し、3Dのカメラがその階の高さを向くようにする

**1-e. 工区割なしでも迷わないようにする**

- パネルの見出しを「2. 工区割（打設を分けるときだけ）」にし、その下に「フロアを一度に打つならここは飛ばして、右の数量をそのまま打設リストに追加できます」と一文添える
- 境界線がないときの工区名「範囲全体」は「フロア全体」に変える（施工階が「モデル全体」のときは「建物全体」）。表示だけで、サーバーが返すラベルはそのまま
- 境界線がないときも「打設リストに追加」ボタンは今通り出す（現状でも動くので、文言と配置だけの調整）

## 改善2：平面表示で上階スラブに隠れないようにする

高さ範囲の既定がSL〜直上SLなので、直上階のスラブ（下面が上限より下）が範囲に入り、真上から見ると柱・梁・壁がスラブに覆われます。計算範囲は変えず、平面表示のときだけ表示を工夫します。

（原本には 5SL〜6SL の平面表示の比較画像：現状・半透明案・1.5m切断案 がある）

5SL〜6SLを平面表示した実際の画面です（hackathon_model.ifc。右の2枚は表示だけ差し替えた試作）。現状は梁・柱は見えるものの、壁（青）がスラブにほぼ隠れます。1.5m切断では壁は見えますが、同じ打設に入る梁と多くの柱が消えるため、半透明案を採用します。半透明では白い三角のちらつきが出るので、下の `depthWrite: false` と描画順の指定は必ず入れてください。

**方式：平面表示ではスラブを半透明にする（既定オン）**

- `paint()` で `state.view === 'plan'` かつ `u.category === 'スラブ'` のとき、不透明度を 0.25 程度にする（`surfaceMat(color, 0.25)`）。輪郭線（`edgeMat`）はそのまま残す
- 透明なスラブを先に描くと下の部材が消えることがあるので、スラブの `renderOrder` を他の部材より後（例：2）にし、`depthWrite: false` のマテリアルを使う
- 平面の表示ボタンの横にトグル「スラブを透かす」を置き、既定オン。オフにすると今まで通りの不透明表示
- 3D表示では適用しない（`setView()` の後に `paint()` を呼んで切り替える）

**補足**

- 別案として「平面表示のときだけ表示の上端を下限＋1.5mで切る（建築の平面図と同じ発想）」もあるが、表示と数量範囲が一致するという要件D19とずれるので、半透明方式を採用する
- 半透明にしても、クリックでの部材選択（`pickMember`）はスラブに当たる。平面表示でスラブが半透明のときは、レイの命中をスラブ以外を優先する（スラブ以外の命中がなければスラブ）

## 改善3：境界線を複線方式にする＋スナップ中の通り芯を強調

JW_CADの「複線」と同じ操作感にします。通り芯をクリック → 寸法を入力 → マウスを動かしてどちら側かを選ぶ → クリックで確定。符号の説明文は不要になります。

**3-a. 操作の流れ**

1. 平面図で通り芯をクリック（現状と同じ `nearestAxis`）
2. パネルに「X3通りから [ 500 ] mm」と寸法欄を出してフォーカス。入力値は常に正の数（マイナスは絶対値にする）。初期値は前回入力した値を復帰
3. マウスを動かすと、カーソルが通り芯のどちら側にあるかで点線のプレビューがその側に出る。寸法欄を打ち替えてもプレビューが追従
4. 平面図をクリック、または寸法欄でEnterで確定。Escで取消。「確定」「取消」ボタンも残す
5. 寸法が0なら通り芯そのものを境界線にする（側の選択は不要）

**3-b. 側の判定**

- 通り芯の始点P0、終点P1、カーソルの平面座標C（`planPoint`）に対し、外積 `(P1-P0) × (C-P0)` の符号で側を決める
- 外積の絶対値が小さい（カーソルが通り芯の真上、目安は `4 * worldPerPixel()` 以内）ときは直前の側を維持する。チラつき防止
- 側が決まったら、既存の `offsetAxisLine(axis, signedOffset)` で線を作る。`signedOffset` は「その側が現在の符号規約（+Xまたは+Y）と同じなら正、逆なら負」で求める。これで保存形式（`{axis, offset, points}`）は一切変わらない
- `state.pending` に `side`（+1 / -1）を持たせる。修正（`editIndex` あり）で開いたときは、既存offsetの符号から初期の側を復元

**3-c. 表示文言**

- プレビュー中は点線の近く（カーソル寄りの端）に `CSS2DObject` で「500」のように寸法を出す
- 境界線一覧（`renderBoundaryList`）は「X3通りから X4側 500 mm」の形式。「X4側」は、同じ向きの通り芯のうちその側で最も近いものの名前。その側に通り芯がなければ「外側」と表記。寸法0なら「X3通り」のみ
- `index.html` の `#pending` 内の「＋は X方向の線なら右…」の説明行を削除し、代わりに「平面図で線を出す側にマウスを向けてクリック」と書く。`#boundaryHelp` も「通り芯をクリック → 寸法を入力 → 線を出す側でクリック」に変更

**3-d. スナップ中の通り芯の強調（`highlightAxis` を置き換え）**

- Three.jsの線は太くできないので、強調用に細長い板（`PlaneGeometry` の Mesh）を通り芯に沿って重ねて描く。色は今の青 `0x1565c0`、不透明度 0.35、`depthTest: false`、`renderOrder` は境界線（9）より下の 6
- 板の幅は画面上で約 8px になるよう `8 * worldPerPixel()` で求め、`pointermove` のたびと OrbitControls の `change` イベントで作り直す（ズームしても太さが変わらない）
- 同時に、その通り芯の記号ラベル（`.gridtag`）に `.active` クラスを付け、`style.css` で白文字＋青背景・太字にする。通り芯ごとのラベル要素は `buildGrid()` で `axisLines` と並べて `axisTags` に持つ
- 強調は、境界線モードでスナップ中（クリック前）と、寸法入力中（基準にしている通り芯）の両方で出す。モードを抜けたら消す
- スナップの許容距離は今の 14px から 18px に広げる。スナップ中はカーソルを `crosshair` にする

## 改善4：通知をヒント欄から分離する

現状は `toast()` が画面下のヒント欄（`#hint`）を上書きして5秒で消えるため、エラーも部材情報も見落とします。種類ごとに出し方を分けます。

| 種類 | 出す場所 | 色 | 消え方 |
| --- | --- | --- | --- |
| 操作ヒント（`updateHint`） | 画面下のヒント欄（今のまま） | 灰文字 | 常時表示 |
| エラー・注意（「先に境界線を…」、工区割を開けない、計算できない） | ビューポート上部中央のトースト `#toast` | 赤系の帯・白文字 | 6秒、またはクリックで閉じる |
| 完了（保存した、開いた） | 同じトースト | 緑系 | 3秒 |
| 部材情報（表示モードでクリック） | クリック位置の近くの吹き出し `#tip` | 白背景・影 | 次のクリック、またはカメラ操作で閉じる |

実装の要点

- `toast(msg, kind = 'info')` に引数を足し、`kind` が `error` / `ok` / `info` で色と表示時間を変える。ヒント欄は一切触らない
- 部材情報は `showTip(ev, html)` を新設。内容は「種別　名称」を太字、1行目、「所属階・材料」を2行目、未計算なら赤で「未計算（理由）」を3行目に
- 計算エラー（`runCompute` / `runUnits` の `!res.ok`）は結果欄の赤文字に加えてトーストも出す
- トーストは複数同時に出さず、新しいもので置き換える

## 改善5：取り下げ（境界線を消すと工区名も消える現状を維持）

境界線を削除したときに工区名も消すのは意図した仕様です。工区名だけを残す場面は想定しておらず、削除ボタンを増やすより線と一緒に消える方が単純なため、この項目は実装しません。後続の番号はそのままです。

## 改善6：工区名のない範囲をハッチで表示する

名前のない範囲は数量に含まれませんが、平面図では白いままなので気づきません。文章の警告を読まなくても分かるようにします。

- `drawZones()` で、`state.regions` のうちどのseedも入っていない範囲に、斜線ハッチのテクスチャを貼った `ShapeGeometry` を描く。テクスチャは `CanvasTexture`（32pxのキャンバスに灰色の斜線1本）を `RepeatWrapping` で繰り返す。不透明度 0.35、`depthTest: false`、`renderOrder` 3
- ハッチの密度がズームで変わらないよう、`texture.repeat` を `worldPerPixel()` から求めて OrbitControls の `change` で更新する（難しければ固定で可）
- 範囲の中心（外周の頂点の平均で可）に `CSS2DObject` で「未設定」と灰文字を出す。工区名モード中は「クリックで工区名を付ける」に変える
- 工区名モードでカーソルが範囲の上にあるとき、その範囲の外周を選択中の工区色の線でなぞる（`pointermove` で `regionOf` を呼ぶ）。どこをクリックするとどこに名前が付くかが事前に分かる

## 改善7：細かい改善

時間があればで構いません。上から順に効果が大きいです。

**7-a. 取り消し（Ctrl+Z）**

- 境界線・工区名・区分の変更前に `state` のうち `boundaries` / `seeds` / `units` を `structuredClone` して履歴配列に積む（最大30件）。Ctrl+Zで戻し、Ctrl+Yでやり直し。戻した後は `renderBoundaryList` / `renderUnits` / `scheduleCompute` / `runUnits` を呼ぶ
- 入力欄（input / select）にフォーカスがあるときはブラウザ標準の取り消しに任せ、横取りしない

**7-b. 工区名の自由入力**

- A〜Fのチップは残しつつ、チップをダブルクリックで表示名を変えられるようにする（例：A → 「1工区」、B → 「東側」）。内部のキーはA〜Fのままで、`state.zoneNames = {A: '1工区', ...}` を別に持つ。表示（平面のラベル、結果欄、区分名）ではこの名前を使う
- 工区割の保存JSONに `zoneNames` を追加（なければA〜Fをそのまま使うので後方互換）

**7-c. 文言**

| 場所 | 今 | 変更案 |
| --- | --- | --- |
| 結果欄のボタン | ＋ 新しい区分として登録 | この数量を打設リストに追加 |
| 結果欄のセレクト | 既存の区分に追加… | 打設リストの既存の行にまとめる… |
| パネルの見出し | 4. 打設区分 | 4. 打設リスト（打設ごとの数量） |
| チェックボックス | 登録済みの部分を除いて計算（二重拾い防止） | リストに追加済みの部分は数えない（二重拾い防止） |
| パネルの見出し | 3. 部材の絞り込み | 3. 数える部材 |

内部の変数名やAPIは変えない。画面の文字だけ。

**7-d. 結果欄の折りたたみ**

- 工区ごとに常時見せるのは、工区名、総数量（大きな数字）、種別内訳の表、未計算の警告、登録ボタンの5つだけ
- 「対象 n 部材　重複控除　単純合計」「材料内訳」「対象部材の一覧」は1つの `<details>` 「根拠を見る」にまとめる
- 末尾の「内訳は柱→梁→…の順で配分した参考値です」は、種別内訳の表の見出しに「？」アイコンを置き `title` 属性で見せる形にする

**7-e. 読込中の表示**

- 「初回は数十秒かかります」の文に、経過秒数を `setInterval` で足す（「読み込んでいます… 12秒」）。止まっていないことが分かる

## 改善8：打設リストを右側に移し、登録後の「0」をなくす

今は数量を登録すると、登録済み分を差し引くため右の数量が0になり、合計は左の「打設区分」を見に行く必要があります。「左＝条件、右＝数量」に揃え、右側で数字が積み上がっていく形にします。

**8-a. 右パネルを上下2段にする**

- 上段「いまの条件の数量」：現在の計算結果（`#resultBody`）
- 下段「打設リスト」：左の「4. 打設区分」（`#unitList`、`#unitSummary`、`#excludeRegistered`）をそのまま右パネルの下に移す。リストの合計は大きな数字で常に見える位置に
- 左パネルは 1～3（施工階・工区割・部材）だけになり、「条件を決める場所」として短くなる
- 追加ボタンを押したとき、下段の新しい行を1秒ほど黄色く光らせて、どこに入ったか分かるようにする（CSSの `@keyframes`）

**8-b. 上段は「全体・登録済み・未登録」の3つを見せる**

サーバーは差し引いた後の `total` と、差し引いた量 `excluded` の両方を返しているので、APIは変えずに表示だけで対応できます。

| 表示 | 値 | 見せ方 |
| --- | --- | --- |
| この条件の数量 | `total + excluded` | 大きな数字（今の `.total` の位置） |
| うち打設リストに登録済み | `excluded` | 灰文字。横に「灰色表示」と添える |
| 未登録（追加できる分） | `total` | 黒文字。追加ボタンの文言を「未登録の 12.34 m³ を打設リストに追加」にする |

- 種別内訳の表は未登録分（今の `by_category`）のまま。見出しに「未登録分の内訳」と書く
- 未登録が0のときは追加ボタンを出さず、「この条件はすべて打設リストに入っています（区分1「5SL～6SL A工区」）」と緑の文字で示す。どの区分に入っているかは、登録済みの区分の条件（高さ範囲と工区の多角形）と今の条件を画面側で比べて求める。判定が難しければ区分名は省略して可
- 「登録済みの部分を除いて計算」のチェックボックスは下段の末尾に移し、文言を「リストに入った部分は灰色にして数えない（二重拾い防止）」にする

**8-c. リストの行をクリックしたらその条件を平面図で強調する**

- 行にマウスを乗せると、その区分の工区多角形（`parts[].polygons`）を平面図で区分の色で縁取りする。離すと消す
- これで「リストのどの行が図のどこか」が対応し、登録ミスに気づきやすくなる
