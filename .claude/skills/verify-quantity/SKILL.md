# 数量の検証（verify-quantity）

数量の定義と許容値は `CLAUDE.md` と `docs/requirements.md` の「検証方法と許容値」が正。
**数字を合わせるために許容値・基準値・テストの期待値を変えない。変えるなら先に利用者に確認を求める。**

## 手順（上から順に。リポジトリのルートで実行）
1. 単体テスト（検証表① 単純形状・② 分割の整合）
   ```
   .venv\Scripts\python.exe -m pytest -q backend/tests
   ```
   - 見るところ：最後の行の「N passed」。failed があれば項目名と値を控える
2. 実モデルの基準値
   ```
   .venv\Scripts\python.exe backend\scripts\quick_check.py
   ```
   - 見るところ：「基準値と一致（±0.01 m³）：全体 ○○ m³、5SL～6SL ○○ m³」。ずれていれば終了コード1で「全体 4377.07 → ○○」と出る
3. 実モデルの通し（検証表②③）
   ```
   .venv\Scripts\python.exe backend\scripts\check_model.py
   ```
   - 見るところ：
     - 「内訳合計-総体積 = 」：絶対値が 0.001 以下（②）
     - 「施工階ごと」の最後の「全体との差」：0.001 以下（②）
     - 「5SL〜6SL: 全体=… A=… B=… A+B-全体=」：A+B−全体が 0.001 以下（工区A＋B＝全体）
     - 「部材単体の体積 vs 既存NetVolume」と「差1%超の種別内訳」：前回（`docs/verification.md` の直近）と件数を比べる（③。合否には使わない）
4. タブレット書き出しの合計＝いまの条件の数量
   ```
   .venv\Scripts\python.exe backend\scripts\site_export_check.py
   ```
   - 見るところ：最後の「結果：すべて合格」。1件でも不合格なら項目名を控える
5. Archicadの数量（`docs/archicad_*.csv`）があれば、検証表④として `quantity-auditor` サブエージェントに比較を頼む。無ければ④は「未実施」

## 記録
`docs/verification.md` の先頭の説明のすぐ後に、新しい節「## 日付 時刻（verify-quantity）」を足し、次の列の表で1項目1行を書く：
`日時｜項目｜期待値｜実測｜差｜判定｜要因`
- 判定は「合格」「不合格」「記録（合否に使わない）」「未実施」
- 要因は実行結果で裏付けたものだけ。裏付けがなければ「未確認」

## 合格条件
- 検証表①②の許容値内（①相対誤差 1e-6、②0.001 m³）
- 基準値（全体 4377.07 / 5SL～6SL 372.90）と 0.01 m³ 以内
- タブレット書き出しの確認がすべて合格

## 失敗したら
- まず「定義を変えたのか（意図した変更）」「バグか」を分ける。定義を変えたなら、利用者に確認を求めてから基準値の更新を相談する
- バグなら、直前に変えたコードを疑い、修正してから手順1からやり直す（フックも自動で検証する）
- 失敗の記録も消さずに残す（直した後の結果は新しい節として追記）
